# Claude Workbench · 第一版设计

用户已确认：制作接近 Codex 对话窗的 Windows 桌面 App，展示实际思考输出与工具操作，直接沿用 CC Switch 管理的本机 Claude Code 配置。

## 结构

- Electron 主进程负责目录选择、本地持久化、Claude Code 生命周期和权限应答。
- React 界面负责项目/会话侧栏、Markdown 流式对话、思考/工具卡片、权限卡片和本地历史检索。
- 使用 Claude Agent SDK 作为本地 Claude Code 进程的通信适配器，明确传入本机可执行文件、工作目录、user/project/local 配置来源及 Claude Code 默认系统提示。模型与密钥由 CLI 自己读取，应用不复制或改写 CC Switch 配置。
- 每轮启动进程时读取当前配置，以 session ID 续聊。应用另存聊天展示记录，避免依赖 CLI 原始历史的清理周期。
- 本地数据位于 Electron userData；每个会话单独保存，原子替换。异常退出保留已写入片段，重启标为中断。窗口关闭且有任务时可留在托盘；无任务则正常退出。

## 界面与范围

左侧是项目与会话；中央是对话和输入框；右侧按需打开会话详情、项目记忆和跨会话引用。支持深浅主题，默认深色，保持清晰、紧凑的桌面工作区风格。

第一版实现：目录选择、新建/续聊、流式文本、接口返回的思考、工具输入/输出、权限与提问、停止、命名/归档、搜索、选定项目的 CLI 历史导入、主动引用其他会话、独立项目备注、Markdown 导出。

不伪造思考内容，不默认将全部历史注入每轮提示。独立项目备注与引用只在用户明确启用时发送，CLI 自己管理的 CLAUDE.md/自动记忆继续交由 CLI 处理。

## 验证

验证事件归并、权限应答、异常/中断、持久化、恢复及项目路径边界。使用隔离的数据目录进行 Electron UI 操作、重启和截图检查。通过继承本机配置进行一次最小真实消息验证；测试结果与未验证范围写入 HANDOFF.md。

## 0.2.0 桌面交付与外观

提供 NSIS 安装版与 portable 单文件 exe，保留固定 appId 和数据目录，在独立版本目录构建，避免覆盖运行中的旧程序。安装时创建桌面和开始菜单快捷方式。

启动和手动同步共用只读检测入口。主进程重新检测本机 CLI，并仅把用户配置路径、时间、状态和模型提示通过 IPC 返回；不缓存或传递配置对象及密钥。模型执行仍由本机 CLI 自行读取所有配置，正在执行的请求不会因刷新而中断。

两张用户提供的原图作为本地资源随应用打包。深色使用黑红狐女和暖色强调，浅色使用冰蓝女王和冰蓝强调；通过全窗图片、渐变遮罩、轻度 blur 和带边框的半透明面板兼顾画面与文字可读性。参考 E:/wyfx/api-test 的处理方式，参考项目保持只读。
