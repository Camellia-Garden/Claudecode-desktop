# Claude Workbench

一个连接本机 Claude Code 的 Windows 桌面工作台。选择文件夹即可开始，项目、历史对话、思考与工具操作都在同一个窗口中查看。

这是一款独立客户端，与 Anthropic 官方 Claude Desktop 无关联。

## 打开应用

推荐打开 **`release/0.3.0/Claude-Workbench-Setup-0.3.0.exe`** 安装版，按向导安装后直接使用桌面或开始菜单中的 **Claude Workbench**。

免安装版是 **`release/0.3.0/Claude-Workbench-0.3.0.exe`**，单文件可直接双击运行，启动时会先解压运行时。本机仍需安装和配置 Claude Code。

也可以打开 `release/0.3.0/win-unpacked/Claude Workbench.exe` 或根目录的 **启动工作台.vbs**，启动更快；移动时请保留整个 `win-unpacked` 文件夹。更新版本时先通过托盘右键菜单或设置中的“退出工作台”退出旧版，再打开新版，原本地记录会保留。

exe 属于本地构建产物，不放入 Git 源码历史；从仓库克隆后可用下方命令自行打包。当前构建未配置代码签名证书。

1. 点击“打开项目文件夹”，选择原先运行 Claude Code 的目录。
2. 在下方输入消息，Enter 发送，Shift + Enter 换行。
3. 要找回原有终端会话，点击右上角“导入终端历史”。只会读取所选项目的记录。
4. 重开应用后，可以从左侧继续上一次的会话。

前提：本机 `claude --version` 可运行，且 Claude Code 已通过 CC Switch 或自己的配置正常连接模型。

## 能做什么

- 项目与会话侧栏、新建/继续、重命名、置顶、归档、全文搜索、Markdown 导出。
- 流式 Markdown、代码高亮、接口返回的思考，以及读写文件、执行命令等工具的输入与结果。
- 修改文件时显示工具返回的文本差异；权限请求和 Claude 的问题在对话里处理。
- 输入框下方或设置页切换“默认权限 / 完全访问”，自动保存并用于后续任务。
- 从选定项目导入 CLI 原始历史，用原 session ID 继续对话。
- 主动引用其他会话，每条消息最多引用 5 段，每段最多带入末尾 16,000 字符的用户/助手正文。
- 独立项目备注，可选择在后续消息中附带；不改写项目的 CLAUDE.md。
- 黑红狐女深色主题、冰蓝女王浅色主题，图片背景、渐变遮罩与半透明毛玻璃面板，也支持跟随系统。
- 启动自动同步本机配置、顶部一键同步、配置读取状态与时间显示。
- Ctrl+K 搜索、Ctrl+N 新对话、停止任务。
- 启动即显示系统托盘图标；关闭窗口隐藏到托盘，任务继续。单击图标恢复，右键菜单或设置可彻底退出；意外退出后显示“已中断”并保留记录。

## 权限与后台运行

输入框下方的盾牌旁可选择 **默认权限** 或 **完全访问**，设置页也提供同一个开关。默认权限按 Claude Code 的规则在需要时询问；完全访问允许读写文件和执行命令，无需逐项确认。选择保存在工作台自身的设置中，重启后保留，不修改 Claude Code 或 CC Switch 配置。

权限切换从下一次发送的任务开始生效，当前任务保持启动时的权限。Claude 需要你提供信息或选择方案的实际问题仍会显示。

点击右上角关闭后，工作台隐藏到 Windows 右下角托盘，进行中的任务继续执行。单击图标恢复窗口，右键选择“退出工作台”或在设置中退出。Windows 可能把图标放入 **^（显示隐藏的图标）**；可将它拖到常显区域。

深浅主题的侧栏、输入区和回答面板均提高了不透明度，回答面板同时加强背景模糊，让文字区域更稳定。

## 如何沿用 CC Switch

应用检测 PATH 与本机原生安装位置，**明确调用本机已有的 Claude Code 可执行文件**。官方 Agent SDK 仅作为通信适配器，并设置：

- 工作目录为选中的项目文件夹。
- 配置来源为 `user`、`project`、`local`。
- 使用 Claude Code 自带的系统提示。
- 不传入独立模型、API Key 或供应商地址。
- 使用工作台选择的 SDK 权限模式；仅选择“完全访问”时启用权限绕过。

每次打开应用会检测本机 Claude Code，并读取 `~/.claude/settings.json` 的安全摘要；设置了 `CLAUDE_CONFIG_DIR` 时使用对应目录。设置页只显示文件路径、模型名称、读取状态和同步时间，不复制密钥、服务地址或完整配置。

在 CC Switch 切换后点击顶部 **同步本机配置**（或设置里的“重新同步”）即可刷新状态。每轮启动时由 CLI 自己重新读取全部配置，当前运行任务继续使用启动时的配置。项目配置、企业策略、会话等可能影响最终模型，设置页的“用户配置模型”仅作提示，输入框标明上轮实际模型。

未找到用户配置文件时仍允许 CLI 使用默认值和继承环境；文件损坏时显示可恢复错误，不把可能含密钥的 JSON 解析错误回传到界面。若只修改了 Windows 环境变量而未保存到设置文件，需要重新打开工作台让它继承新的环境。

这保留了你现有的模型/供应商配置，但图形界面与终端交互不保证逐项一致。完全依赖终端界面的插件、自定义交互和未适配的 SDK 事件仍需单独验证。

## 思考与记忆的边界

思考面板只展示模型/中转接口实际返回的内容。不支持思考输出的模型只显示回答和工具操作，应用不会生成虚假的推理记录，也不推断模型内部的实际思考耗时。

历史列表供人浏览；继续原会话会恢复该会话上下文。其他会话不会自动全部注入模型，需要主动引用或启用项目备注。Claude Code 自身的自动记忆仍由本机配置控制。

这版主要面向文字与编码工作，暂不包含图片上传、完整编辑器、自动跨会话摘要、远程多人协作或自动更新。

## 数据保存

聊天展示记录独立保存于应用的 `userData/workspace`，每个会话一份 JSON。设置页显示本机实际路径。CLI 也会按自己的规则保存原始会话；两个位置不是同一份文件。

本应用不保存单独的 API Key，也不上传历史索引。发送给模型的消息、明确引用的历史及启用的备注，仍会经由你配置的模型服务处理。

归档只是从默认侧栏隐藏，搜索和归档列表仍可找到。应用没有删除原始 CLI 历史的功能。若需要备份，请在任务结束并退出应用后备份 `workspace` 目录。

## 开发与验证

要求 Node.js 22+，在 Windows 上开发和验证。

```powershell
npm install
npm run dev
```

开发时网页内容热更新；修改 `electron/` 后重启开发进程。

```powershell
npm run build          # 类型检查、网页与主进程构建
npm run icons          # 从 assets/icon-source.png 重新生成 PNG 和多尺寸 Windows 图标
npm test               # 核心行为测试，无模型请求
npm run test:desktop   # 隔离目录中的 Electron UI 与重启测试
npm run test:tray      # 原生托盘创建、关闭隐藏、点击恢复与菜单退出
npm run test:permissions # 真实模型执行 Write/Bash，验证完全访问和后台继续
npm run test:connection # 使用本机模型，读取测试文件并验证重启续聊
npm run package        # 可直接运行的 Windows 文件夹
npm run dist           # 安装版 + 便携单文件 exe，输出 release/版本号/
```

`test:connection` 和 `test:permissions` 会调用你配置的模型服务，可能消耗额度。测试项目与应用记录位于忽略的 `.test-data/`，截图与测试摘要位于 `test-results/`；CLI 自身也会保存这次测试的会话记录。

打包后可运行 `node scripts/test-smoke.mjs` 检查独立 EXE、主题与最小窗口。`node scripts/test-packaged.mjs` 在真实连接测试成功后，使用其测试项目验证 CLI 历史导入与续聊，也会调用模型。

0.1.0 已验证真实工具调用、同会话恢复、打包 EXE 历史导入和续聊，使用当时 CC Switch 配置返回的 deepseek-flash 模型。

0.2.0 核心测试增至 19 项；桌面测试还覆盖启动同步、运行中修改配置后的手动同步、密钥不进入 IPC、深浅壁纸映射和历史/主题重启保留。测试脚本会将结果写入忽略的 `test-results/`，无需把本机记录上传仓库。

0.2.0 已在本机通过打包启动、真实 CLI 历史导入及续聊、最小窗口检查；`node scripts/test-portable.mjs` 已验证单文件 exe 解压启动、读取当前配置、手动同步、壁纸加载和正常退出。安装版已生成，安装向导未在本机执行。

0.3.0 核心测试为 24 项，覆盖权限持久化、旧设置兼容、运行中切换不提权和真实问题保留；桌面 UI 和原生托盘测试通过。真实 Claude Code 已执行 Write 与 Bash，零逐项授权提示，关闭窗口后任务继续完成。

0.3.0 已通过打包 EXE 检查，确认版本、自定义图标、深浅壁纸及 900×620 下权限选择和发送按钮无重叠；便携单文件已通过启动、配置同步、关闭到托盘及彻底退出测试。安装版已生成，未执行安装向导。

应用图标使用用户提供的橙发角色原图，窗口、托盘、应用内标识和 Windows 打包图标保持一致。原图保存在 `assets/icon-source.png`，生成时等比缩放并补齐透明边缘；Windows 图标包含 16–256 px 的七种尺寸。替换原图后运行 `npm run icons`，再重新打包即可。

旧构建及历史测试缓存、截图会在验证后清理。测试目录会在运行相应脚本时重新生成；需要验证真实历史导入时，先运行 `npm run test:connection` 创建隔离测试会话。

## 结构

```text
electron/       本机 CLI 检测、SDK 适配、消息归并、存储、IPC 与窗口
src/            React 聊天界面、侧栏、弹窗及样式
src/assets/     用户提供的深色/浅色背景图片
shared/         主进程与界面共享类型
scripts/        开发启动、图标、桌面/真实连接测试
tests/          流式消息、存储与执行生命周期测试
docs/design.md  第一版设计与范围
```

不需要运行网页服务器即可使用打包后的应用。模型密钥、个人配置、应用聊天数据和测试生成的会话不得提交到仓库。
